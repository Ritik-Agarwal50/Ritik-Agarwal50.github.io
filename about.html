About Ritik Agarwal

I am an independent smart contract security researcher and security engineer based in Ahmedabad, India. I specialize in identifying high-severity business-logic vulnerabilities, invariant violations, and EVM execution edge cases in decentralized protocols.

Background & Philosophy

My engineering background started in general software development and hackathons before shifting to EVM internals. Rather than viewing smart contracts as static text to run through automated scanners, I view them as state machines where discrete state transitions, precision rounding, and reentrancy execution sequences can lead to catastrophic insolvency.

I realized early on that writing functional code is only half the engineering challenge; rigorously proving that code cannot be forced into invalid economic states is where the real depth lies. This realization prompted my transition from application development to deep offensive security research and formal invariant testing.

Audit Methodology

  1. Invariant Mapping & Intent Modeling: Before looking for bugs, I study the protocol's mathematical architecture. What are the core invariant properties? Can total borrowed assets ever exceed supplied liquidity? Can exchange rates ever decrease? What state assumptions does the contract rely on?
  2. Adversarial Threat Modeling: I systematically interrogate state transitions: flash loans, oracle latency, unexpected token behaviors (fee-on-transfer, rebasing, ERC-777 callbacks), integer truncation across casting boundaries, and transaction ordering dependencies.
  3. Deterministic Proof-of-Concept (PoC): Speculative vulnerability reports provide little value. Every high or medium vulnerability I document is paired with a reproducible Foundry test suite that mathematically validates the exploit path, calculates exact capital loss, and validates the mitigation.
